{%- comment -%} Navigation sort (JTD-compatible). Parameters: pages - array of pages to order sort_by_date - optional; when true, every page in the set is ordered by publish date instead of nav_order/title Ordering precedence: 1. If sort_by_date is true, the whole input sorts chronologically and FIRST, newest first unless `stygian.nav.date_order: asc`. 2. Then explicit `nav_order` values: numbers (int/float) before strings. 3. Then pages without `nav_order`, ordered by `title` (numbers, then strings). String comparisons honor `nav_sort: case_insensitive`; ties fall back to insertion order (stable enough for docs sites). Why an explicit opt-in rather than "sort pages that have a date": Jekyll assigns a `date` to every page in every collection by default (the collection scan time), so a `date != nil` test cannot separate blog posts from docs pages. Collections therefore opt in individually, which is how a docs site becomes a blog site without its reference docs reordering themselves. Wiring: set `just_the_docs.collections..sort_by: date` to make that collection date-ordered, or `stygian.nav.sort_by: date` to make the default collection date-ordered. `stygian.nav.date_order: asc` flips newest-first to oldest-first. Constraint: `where_exp` cannot take a `|` inside its expression string, so every derived split uses `group_by_exp` or a plain `sort`.
